# 阶段 04：采购与库存

## 目标

交付采购申请、采购订单、采购入库和基础库存管理闭环，为后续销售履约与财务自动记账提供可追踪的业务单据和库存流水。

## 业务规则

- 所有采购和库存记录携带 `organization_id`，接口只允许访问当前组织的数据。
- 采购申请必须引用有效的供应商、仓库和库存管理商品；1.0 演示流程创建后自动进入已批准状态。
- 采购订单可关联已批准的采购申请，也可以独立创建；订单行记录订购、已收和剩余数量。
- 入库支持分批收货，收货数量不得超过订单行剩余数量；每次收货都生成入库单和库存流水。
- 库存按“组织 + 仓库 + 商品”维护余额，入库和调拨入库使用移动加权平均成本。
- 调拨必须发生在两个不同仓库之间，并为转出和转入分别生成库存流水。
- 盘点以锁定时库存余额为账面数量，盘点差异通过库存调整流水落账。
- 库存调整的金额为 `abs(quantity_delta * unit_cost)`；超过组织审批阈值时创建工作流任务，审批通过后才更新库存。
- 库存流水使用业务单据和流水类型做幂等约束，重复请求不得重复增加或减少库存。
- 已发生收货的采购订单不可直接取消；全部收货后订单进入已收货，部分收货后进入部分收货。

## 交付范围

- 后端：采购申请、采购订单、采购入库、库存余额、库存流水、调拨、盘点、库存调整及高风险调整审批接口。
- 前端：采购申请/订单工作台、采购订单收货、库存余额/流水查询、调拨和库存调整表单。
- 数据库：Flyway `V5__procurement_inventory.sql`，包含采购单据、库存余额、库存流水及库存操作表。
- 接口契约：`docs/api/openapi.yaml` 中新增采购与库存请求模型及接口路径。

## 阶段验收标准

1. 可创建采购申请并生成采购订单，订单显示已收、剩余数量。
2. 可对采购订单行部分或全部收货；库存余额增加并生成唯一库存流水。
3. 可在两个仓库之间调拨，转出仓库减少、转入仓库增加，成本保持可追踪。
4. 可提交盘点并将差异写入库存流水；库存不足时拒绝负向调整。
5. 低风险库存调整立即完成，高风险调整进入待审批状态，审批通过后才落账。
6. 未登录或无仓库权限的用户不能执行采购收货、调拨、盘点和库存调整；审批操作仅限管理角色。
7. 前端和后端质量门禁通过：`pnpm verify:web` 与 Maven API 测试全部通过。

## 1.0 简化与 2.0 边界

本阶段为单组织演示版，保留组织隔离字段但不实现多组织切换。采购申请采用自动批准以保证演示闭环，完整的多级采购审批可复用工作流中心后续扩展。

以下能力明确不在 1.0：退货与退款、批次和序列号、库位、保质期、库存预留、国际贸易税务及供应商协同门户。这些能力进入 2.0 规划。
