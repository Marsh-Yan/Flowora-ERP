# 不同汇率退款验收（R6-H）

退款支持明确输入不同于原收付款的会计汇率和汇率日期，仍须同组织、同交易方、同交易币种、真实已过账普通来源。正汇率最多8位，汇率日期不早于原汇率日期且不晚于退款记账日期，本位币退款及其原单汇率须1。页面默认原汇率，不获取市场报价，金额/汇率/日期改变须重新确认，创建草稿与过账分开；已有权限、来源额度、组织财务锁、银行对账及期间规则保留。

V23新增 refund_source_base_amount 与实际差额凭证链接，并给更正历史增加差额反向凭证链接，不改历史迁移或补猜旧数据。创建草稿同时保留原账面金额；源本位币金额减去活动核销的源账面金额及DRAFT/POSTED退款保留账面金额，最后一笔退款取精确剩余，收拢4位折算尾差。历史空字段保留，旧同原汇率退款按其已有本位币金额参与剩余计算，历史显示空值而非伪造凭证。交易币额度仍按金额和实际状态管理。

过账先按退款汇率记现金/同币银行及往来，再按“退款本位币金额减原账面金额”差额生成独立 REFUND_EXCHANGE 本位币/汇率1凭证。客户退款金额增加为损失、减少为收益；供应商反向；使用现有 FX_GAIN/FX_LOSS 映射，不做差额除汇率再折算。两张凭证同事务写入；缺映射或期间关闭整体回滚。撤销同事务反向两张实际关联凭证，释放额度并保留两张反向凭证链接；通用总账入口不能单独反转退款差额或其反向凭证。差额0不建无意义凭证。

页面历史显示退款汇率/日期、源账面金额、带符号的差额和实际差额凭证，撤销记录分别标注主凭证与差额凭证的反向ID；差额正负不是损益方向标签。桌面扩宽对话框，小屏横向滚动。等待禁止重复/关闭、同内容不确定结果显式重试保留key、迟到读取/动作代次保护均沿用。
