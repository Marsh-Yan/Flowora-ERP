# 原生订单确认与取消访问契约（R5-K，2026-10-03）

适用于 local/production 的 `/api/v2/sales/orders/{id}/confirm|cancel` 和 `/api/v2/procurement/orders/{id}/confirm|cancel`。角色名称不授予操作能力；每次动作使用当前组织有效成员的最新权限、部门和范围。

## 权限及范围

四个动作同时要求对应模块 `view` 和 `submit`。控制器在调用原有事务服务前，使用订单详情读取同一 `OrderReadScope` 校验该订单：

| 范围 | 可执行订单 |
| --- | --- |
| ALL | 当前组织订单；组织外 ID 仍由原服务拒绝 |
| SELF | 当前用户拥有的销售订单/采购订单 |
| DEPARTMENT | 拥有人在当前组织有效成员中、且属于当前用户部门的订单；没有部门时拒绝 |
| ASSIGNED | 尚无原生订单指派策略，拒绝，包括用户自己的订单 |

缺少查看或提交能力、成员停用或范围越界返回 403，在订单确认、取消、取消行和库存预留释放之前拒绝。旧会话的 ALL→SELF、查看/提交权限撤销、部门更换及成员停用在下一次请求生效。

原生草稿创建继续只要求对应 `create`，不要求 submit 或 ALL；本批没有改变创建、来源行关联、状态版本与取消规则。可读订单的版本冲突保持 409；原有已确认订单的确认重放仍返回当前确认状态；组织外 ID 在 ALL 下保持原确认 409 / 取消 404，未统一既有状态码。

## 验证

- `NativeOrderActionAuthorizationTest`：8 项真实方法安全代理，验证查看/提交组合、事务调用前的范围检查及顺序、最新身份与撤权/停用、SELF create-only 草稿入口。
- [native-order-actions-smoke.ps1](../../tools/verification/native-order-actions-smoke.ps1)：18 个真实 HTTP 场景，覆盖两个模块的合法 ALL/SELF/同部门动作、只读/无 view、部门越界与空部门、ASSIGNED、旧会话范围/部门/权限变化、停用成员、跨组织、版本冲突和 v1 只读。
- 拒绝操作比较所列 24 张订单、流程、库存、凭证、审计表的完整有序行；跨组织场景分别比较父、子组织。SQL 只读，所有业务夹具通过 HTTP 创建，只停用/归档本轮自建账号组织。

本地仅连接已授权 `audit_flowora` / MySQL 13306、Redis 16379、API 18080；CI 使用一次性隔离实例，并保存脱敏用例结果。完整后端 188 项、Web 24 项及 lint/type/build 通过；最终 PR/head/CI 以当次证据为准，不沿用旧构建扫描。
