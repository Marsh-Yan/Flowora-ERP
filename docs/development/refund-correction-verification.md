# 退款取消与撤销验收（R6-G）

退款管理新增两种明确动作：DRAFT 退款可由 finance:create 用户取消，状态变为 CANCELLED，不产生凭证；POSTED 且来源明确的退款可由 finance:post 用户撤销，按原汇率生成反向凭证并变为 REVERSED。均要求 finance:view、当前组织 ALL 范围、实际退款 ID/版本、日期、非空原因和页面确认。取消或撤销后不再占用原收付款可退余额，原单、退款、更正原因、操作人和凭证关系全部保留。

V22 新增退款更正历史表，不改历史迁移或猜测旧数据来源。同一退款只允许一次更正；组织内请求键和内容绑定，相同内容明确重试返回原结果。业务更正与银行对账共用组织财务锁，避免匹配与撤销竞争；已确认对账须先显式解除，已核销退款不得直接更正。撤销记账期间须开放，日期不得早于原退款。原退款凭证及其反向凭证不能通过通用总账撤销入口独立反转，避免凭证和业务状态分离。历史无来源草稿可取消释放保守占用，历史无来源已过账退款继续暂停撤销。

页面另选实际草稿或已过账退款，填写原因并确认；原因或退款改变须重新确认。写入不自动重试，相同内容明确重试保留请求键，动作后重读历史；等待禁止重复操作和关闭，组织/权限/关闭代次保护沿用退款页面。历史显示 CANCELLED/REVERSED、原因、日期、操作人和反向凭证 ID，编号及状态保持可读，小屏表格可横向滚动。

本地 Web168 项、lint、类型检查及构建通过；真实 MySQL FinanceMySqlTest20 项失败、错误、跳过均0。新增数据库测试覆盖客户/供应商对称取消与撤销、余额释放、原因与幂等重试、同键内容冲突、反向凭证/原汇率/借贷平衡、通用凭证入口限制、银行对账先解除、关闭期间原子回滚以及实际事务并发过账与取消只能成功一个。新增页面测试覆盖实际 ID/版本、原因及确认、权限、历史凭证和显式重试。

普通页面使用新 R6G Browser Orders 合成组织；SQL 仅预置主数据、账户、岗位和开放期间，没有预置财务交易。页面创建并过账 RC-1792207326498，100 USD、汇率7.2 CNY；创建40 USD草稿 CR-1792207429845，可退100→60，填写原因取消后恢复100；再创建40 USD退款 CR-1792207464845，保存/过账后可退60，明确撤销后恢复100。整页刷新重开仍有两条更正历史、原因和实际反向凭证 ID，原汇率保持7.2。

只读 SQL 核对：原收款保持 POSTED/allocated0；两笔退款分别 CANCELLED/REVERSED，来源均为实际原收款；更正历史两条、实际操作人一致；取消草稿无凭证，已过账退款凭证 REVERSED，反向凭证 POSTED 且 reversal_of_id 指向原凭证。三张凭证逐张交易币/本位币借贷平衡，历史本位币借贷各1296 CNY，现金映射账户净借720、应收控制净贷720 CNY，与100 USD预收一致。未创建发票、贷项或核销，不宣称已付发票退货退款完整链路；浏览器仅实际验收客户现金退款，供应商和银行对账限制由数据库测试覆盖。
