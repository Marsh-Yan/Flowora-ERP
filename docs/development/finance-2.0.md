# Flowora ERP 2.0 财务与项目核算开发规则

## 范围

M4 在 1.0 基础财务之上引入正式发票、红字单据、收付款核销、完整冲销、期间管控、银行对账、多币种重估、预算执行与项目计费。M3 业务单据仍是事实来源，财务单据不得反向改写库存或履约数量。

## 日期与金额口径

每张财务单据分别保存业务日期、会计日期、汇率日期和到期日。交易币种金额、基础币种金额与汇率在创建时固化；所有金额按四位小数保存。会计日期决定期间，关闭期间禁止新增过账。

R3 补充规则：汇率最多八位小数，凭证金额最多四位小数，不接受负借方/贷方。换算采用逐行 `HALF_UP` 到四位；写入凭证或创建期间前同时检查原币与本位币借贷合计。原币平衡但本位币因逐行舍入不平时返回 `409 JOURNAL_BASE_NOT_BALANCED`，整次过账回滚，发票保持草稿；不自动选择尾差科目。两行 EUR 0.0001、汇率 0.5 即按此规则拒绝。

## 发票与匹配

- 销售发票引用销售出库行或项目计费依据；供应商发票引用采购入库行。
- 红字单据必须引用原已过账发票，并校验累计红冲金额和数量不得超过剩余值。
- 供应商发票比较订单价格、入库数量与发票税额；超过组织容差时进入异常状态，需具备例外审批权限后方可过账。
- 创建接口要求幂等键；同组织同键重放必须返回同一单据。
- 收货/出库来源必须同时匹配组织、实际行、已过账来源单和对应供应商/客户。采购供应商从收货单关联采购单读取。销售/采购来源不能相互替代。
- 采购发票的默认借方清理来源收货凭证实际使用的暂估贷方科目；旧兼容收货曾直接暂估到应付科目时也不能重复增加负债。没有来源凭证时使用 ACCRUED_PAYABLE 映射。同一发票行混用不同暂估科目的来源时要求拆行；显式科目仍按录入值过账。
- 同一发票行中库存来源的数量合计必须等于发票行数量。过账、核销、撤销和重估先取组织财务设置行锁，再取单据和排序后的来源行锁；累计消费量使用 MySQL 当前读，避免 REPEATABLE READ 旧快照允许两个草稿超量过账。累计已过账数量不得超过收货验收/出库数量减退货数量。红字过账后按原发票行的红冲比例释放各来源的可开票量。未关联库存来源的手工服务发票仍可使用；项目计费继续使用项目模块的消费规则。

## 总账与期间

自动凭证由语义过账映射解析科目。每张凭证必须至少两行、借贷互斥、交易币与基础币分别平衡。已过账凭证不可编辑，只能创建反转凭证。期间关闭保存检查项和结果；重新打开必须记录原因、操作者和请求键。

## 收付款与银行对账

收付款过账后才能核销。核销必须满足组织、往来方和币种一致，且不能超过付款或发票剩余金额；核销可反向撤销并保留审计记录。银行流水以账户和外部参考号去重，对账记录保存流水、付款、匹配金额和差额，撤销后恢复流水未匹配状态。

核销汇兑损益按本位币差额直接记账，汇率为 1，避免除以汇率再乘回引入额外舍入。客户正差额为收益、供应商正差额为损失。凭证的 `source_type=REALIZED_EXCHANGE`、`source_id=核销ID` 是关联依据。撤销在原核销的发票会计日期创建原凭证的反转，恢复付款和发票余额；期间关闭、缺失/异常汇兑凭证时整笔失败。相同撤销键可重放，不同键再次撤销返回冲突；原凭证和撤销记录保留。历史错账仅由另行审查的数据修复处理，不在本阶段自动改写。

银行对账同时校验组织、账户、币种、金额和收支方向：RECEIPT/SUPPLIER_REFUND 对应正银行流水，PAYMENT/CUSTOMER_REFUND 对应负流水。反向流水不能通过绝对值比较误匹配。

外币重估以组织设置行锁串行执行，同键返回原重估；同币种存在未反转重估凭证时拒绝再次执行。核销和红字在相关重估反转前同样拒绝。重估差额直接用本位币记账，避免再次换算；红字发票不作为独立外币未结余额重复计算。`reversalDate` 是计划日期，**不代表后台已自动反转**。有 `finance:post` 权限者通过 `POST /api/v2/finance/revaluations/{id}/reverse?accountingDate=YYYY-MM-DD`、Idempotency-Key 和 `{reason}` 显式反转；关闭期间或早于原会计日期的操作失败。实际反转日期、原因与操作者保存在反转凭证中。

## 财务页面与错误契约

local/production 的旧财务过账入口使用同一个 v2 凭证引擎补齐会计日期和本位币行；旧接口没有汇率参数，因此只允许本位币，外币须使用带显式汇率的 v2 发票/付款入口。库存成本始终按组织本位币记账。兼容收货按收货当天记账，应付到期日另存为 30 天后，不能将到期日作为凭证日期。兼容报表按凭证本位币行汇总，包含 POSTED 和 REVERSED 原凭证以及反转凭证；不能仅排除已反转原凭证，否则会重复冲减。旧接口展示凭证明细仍保留原币金额。R3 不自动回填此前缺少会计日期/换算依据的历史凭证，升级前须单独核查这些历史记录。

财务工作台默认使用浏览器本地日期的月初至当天，显式向 dashboard 传 `from`/`to`。所选区间用于期间收支及按会计日期过滤的发票/收付款、按交易日期过滤的银行流水；应收/应付余额和待处理数量仍为当前状态。各区块独立加载，指标失败显示错误和未知值，不显示业务零值，其他成功列表仍可用；重新加载按钮可重试。日期切换时旧请求不能覆盖新结果。

缺参数、无效日期/枚举、不可读 JSON 和输入校验返回 400；未知路由/资源返回 404；业务状态冲突返回 409；认证/授权仍为 401/403。框架输入错误的响应不包含异常详情，真正服务异常保留 500、requestId 和服务端日志。

## R3 验证入口

- `FinanceMySqlTest` 仅在 `FLOWORA_R2_MYSQL_URL=jdbc:mysql://127.0.0.1:13306/audit_flowora?...` 时启用；每个用例创建独立组织，清理只针对自己的夹具。
- `tools/verification/finance-smoke.ps1` 固定访问隔离 API 18080，需要合成账号 `FLOWORA_R3_HTTP_PASSWORD`。覆盖真实 HTTP 来源开票、舍入拒绝、核销冲回、幂等重放、错误状态和 dashboard。此脚本会写测试业务单据，不用于业务环境。
- Web 组件回归覆盖默认/选定日期传参与单区块失败；真实浏览器走查使用专用前端端口并仅代理隔离 API。可用 `FLOWORA_DEV_API_URL` 指定开发代理，默认仍为 localhost:8080。

## 项目计费与利润

项目支持固定价、里程碑、工时材料三种计费模式。工时、费用和里程碑经审批后生成不可超额消费的计费依据；生成项目发票仅创建草稿，仍由财务人员复核过账。利润视图分开展示合同额、待计费、已开票、已过账收入、已过账成本、管理工时成本和毛利。

## 月结演练顺序

1. 清理匹配异常和未过账正式发票。
2. 完成收付款核销并处理未匹配银行流水。
3. 执行外币余额重估并复核重估凭证。
4. 检查试算平衡与预算执行差异。
5. 执行期间关闭检查，保存检查明细。
6. 关闭期间后验证新增过账被拒绝；如需重开，必须使用独立权限并填写原因。

## 验收底线

- 交易币与基础币总账均借贷平衡；
- 幂等重放不产生重复发票、付款或凭证；
- 发票、红字、核销、反核销和银行对账均可追溯到操作者与来源；
- 项目计费依据不会被超额或重复消费；
- 演示数据可重复重置，角色权限不会残留或重复。
