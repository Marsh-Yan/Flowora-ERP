# 工作台与分析的数据范围（R5 第三批）

本批基于 PR27 合并提交 `a4e07361975bc1369ceab99e1802e9756827189a`。在授权隔离库复现并修复 7 个失败场景：未分配部门的工作台泄漏组织数量、项目部门计数与详情不一致、成员项目风险数为零、月度分析忽略模块权限、月度分析忽略 SELF/DEPARTMENT、受限范围可请求跨组织全量金额、跨组织金额忽略目标模块权限。新增目标组织权限及范围重载，阻止从当前组织权限推断其他成员组织权限。

## 当前读取规则

| 数据 | ALL | DEPARTMENT | SELF | ASSIGNED |
| --- | --- | --- | --- | --- |
| 销售/采购列表、工作台计数、月度订单金额 | 当前组织 | 当前部门的 ACTIVE 成员拥有的单据；无部门为零 | 当前用户拥有的单据 | 未建立订单受派关系，返回空结果 |
| 项目列表/详情、风险计数 | 当前组织 | 项目自身 department_id；不使用经理所属部门 | 当前用户为经理 | 当前组织、当前项目的 active 成员关系 |
| 工作台库存/财务组织汇总 | 有相应模块 view 权限时返回 | 不返回组织级卡片 | 不返回组织级卡片 | 不返回组织级卡片 |
| 月度正式财务收入/费用/毛利 | finance:view 时返回 | 没有财务行级规则，返回 null | 返回 null | 返回 null |
| 跨组织全量汇总 | 每个目标组织重新加载身份；必须有该组织 ALL 与 analytics:cross-org | 403 | 403 | 403 |
| 导出 | 仍需 analytics:export 和资源 view 权限 | 仅销售/采购，固化部门并在下载时复核 | 仅销售/采购，固化范围并在下载时复核 | 不支持，403 |

月度销售和采购还分别需要 `sales:view`、`procurement:view`。未经授权的模块字段是 null，不能以 0 冒充真实金额；只有允许读取的域生成月份，避免从隐藏数据推断日期。跨组织候选只来自有效成员关系，并按每个目标组织的权限分别返回销售或财务字段；撤销 target 的 cross-org/ALL 后不再返回该组织行。缺少身份验证器时拒绝跨组织汇总。

浏览器用“—”显示不可见金额；SELF/DEPARTMENT/ASSIGNED 不请求组织级跨组织汇总。导出按钮根据模块权限和已有支持范围显示；服务端仍独立验证，不依赖隐藏按钮。没有新增数据库迁移或修改历史数据。组织级财务/库存其他 API 在第四批明确为 ALL + 操作权限，仍没有行级策略，见 [组织级访问边界](organization-module-access.md)。
