# 原收付款更正验收

2026-10-17，R6-J。普通 RECEIPT / PAYMENT 增加取消草稿与业务撤销；先前总账直接反转会留下 POSTED 业务单。本批通用反转拒绝原收付款及其反向凭证，业务入口在同一事务中写反向凭证、业务状态与更正审计。既有退款业务更正保持原入口。

## 业务规则

- `POST /api/v2/finance/payments/{id}/cancel-payment`：组织 ALL 范围的 finance:create；仅当前版本 DRAFT。
- `POST /api/v2/finance/payments/{id}/reverse-payment`：组织 ALL 范围的 finance:post；仅当前版本 POSTED。页面另需 finance:view。
- 请求含 Idempotency-Key、version、accountingDate、非空 reason（最多500字符）。同 key 仅允许同原单、动作、版本、日期及原因重放；不重复创建凭证或审计。
- 原单须无活动核销，header allocated_amount 也须为0；任何活动关联退款（DRAFT / POSTED）均阻止更正。同交易方/分类/交易币的无来源历史退款也须先处理。
- 已确认银行对账须先显式解除。取消草稿不生成凭证；已有真实凭证的草稿不能当作未过账草稿取消。
- 撤销日期不得早于原记账日期，撤销期间须开放；按原币种、原汇率和原分录反向记账。需要唯一实际原凭证，头金额、日期、币种、汇率、往来与两条实际借贷/本位币分录一致且未反转。缺失或矛盾历史证据留待专门核对。
- 组织财务锁串行化过账、核销、退款、银行对账及更正；依赖行使用当前锁定读。V25一次性审计保留动作、原因、操作人、日期、实际反向凭证、来源版本及请求键，原业务和分录不删除。

页面入口为财务运营工作台的“原收付款更正”，明确选择原单、日期、原因及确认。选择/版本/占用/日期/原因变化后重新确认；busy期间禁重复/关闭。结果不确定先刷新历史，同内容可显式重试同key，不自动重试。查看权限可读取全部日期的持久历史。

## 验证

本机真实隔离 MySQL：FinanceMySqlTest 38项，失败/错误/跳过均0。新增6项覆盖客户/供应商取消与反转、金额与往来余额、幂等及原因绑定、核销解除（包含活动记录与头金额不一致）、草稿/已过账/无来源退款阻止及逐笔恢复撤销、银行对账解除、关闭期间原子回滚、错误版本/类型/日期/原因/矛盾分录、并发退款预留与原单撤销只能一方成功。既有来源恢复的当前状态回归改用精确合成组织内并发SQL模拟历史导入改变JE状态，通用反转现已拒绝业务原单；该SQL仅是一次性DB测试夹具。

Web 180项通过，新增5项覆盖明确选择与重新确认、按create/post区分动作、活动核销及退款占用、只读历史与SELF范围、结果不确定同key重试与关闭迟到回调。lint零警告，类型检查和生产构建通过（保留现有chunk体积提示）。初版测试桩的文本框选择器与多余/缺失类型字段已修正，以最终结果为准。
