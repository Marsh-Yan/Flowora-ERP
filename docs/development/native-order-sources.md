# 原生订单来源行关联

采购订单的来源为 `PURCHASE_REQUEST`，销售订单的来源为 `SALES_QUOTE`。无来源的独立草稿仍可创建；填写来源时，单据类型、单据 ID 和真实行 ID 必须同时提供。

来源必须属于当前组织、行必须属于所选单据，单据必须为 `APPROVED`。供应商或客户及物料必须与订单匹配，销售报价币种必须与订单一致。引用共享申请或报价需要相应模块查看能力和 `ALL` 范围；沿用入口对当前成员和创建能力的检查。

来源校验和订单、行、来源关联、幂等记录写入处于同一事务。按来源单据和行 ID 的固定顺序读取并使用 MySQL `FOR UPDATE`，串行核对来源数量；两个原生创建入口仅将自己的事务设为 READ COMMITTED，已有分配使用锁定当前读，避免旧快照和范围间隙锁阻塞无关来源订单。其他动作和数据库全局隔离配置不变。来源类型统一为大写，`linked_quantity` 保存当前订单行数量。本人重复提交沿用原重放规则，关联不会重复写入。

采购申请、销售报价响应新增可选 `lineId` 字段；无行的历史记录返回 null，不参与来源选择。页面使用真实 `lineId`，来源信息保存在对应订单行上。新加行独立，清空选择去掉来源，删除来源行不会把关联转移到剩余行，重新打开表单重置来源选择。

同一来源行允许拆成多行或多张订单；每行先按数据库 DECIMAL(19,4) 的四舍五入精度归一化，同一请求中重复引用的数量再合计，再与既有分配相加。草稿和其他有效状态的订单均占用额度，整单取消后释放。累计数量不得超过来源行 quantity；数量不足返回 409 SOURCE_QUANTITY_EXCEEDED，整笔创建回滚，前端保留表单并提示调整数量。

来源关联作为历史保留，不因取消而删除；统计时排除已取消目标单据。缺失目标订单或目标类型不符的历史关联仍保守计入，需单独只读预检及人工处置。本阶段不新增迁移、不改写历史单据，不变更旧兼容入口的来源分配方式。请求正文指纹和完整真实浏览器验收仍待。

验证：真实 MySQL 测试类新增 12 项业务回归，包含拆单、数量边界、取消释放及同来源/不同来源的双方并发。前端 34 项通过，包含来源表单及数量不足反馈。完整后端与远程 CI 结果见本批 PR 交付说明，不将源码观察计为已验证。

组件测试使用原生下拉框替身，不等同于真实浏览器 Element Plus 操作验收。本地仅运行仓库业务自动化测试，未额外运行安全探测脚本；GitHub CI 沿用原配置。

事务测试通过真实 Spring 事务代理执行来源订单创建，不手工复制入口隔离级别。无关来源并发测试在两边分配读取结束后使用屏障同步，再验证双方成功；该测试在默认 REPEATABLE READ 下确认了范围锁死锁并在修复后回归。设计参考：[MySQL 事务隔离说明](https://dev.mysql.com/doc/refman/8.0/en/innodb-transaction-isolation-levels.html)。

报价有效期使用组织配置的 IANA 时区对应的日历日期，有效期当天可引用，次日起新创建返回 409 SOURCE_QUOTE_EXPIRED。原生及兼容销售创建入口共用规则；创建报价的过去日期校验也使用该日历。组织时区配置无效返回 ORGANIZATION_TIMEZONE_INVALID，避免静默使用服务器时区。

销售报价响应 sourceEligible 由服务端按批准状态和有效期计算；页面仅列出可用来源，仍保留后端最终校验及过期提示，防止列表加载后跨日。报价状态不自动改写，已创建订单仍可确认，本人原请求重放仍返回原订单。无数据库迁移。固定时钟回归覆盖最后一天、跨午夜、同一时刻的不同组织日历、已有订单重放和事务回滚；组件测试验证隐藏过期报价及保存时过期反馈。
