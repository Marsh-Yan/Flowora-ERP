# 原生订单来源行关联

采购订单的来源为 `PURCHASE_REQUEST`，销售订单的来源为 `SALES_QUOTE`。无来源的独立草稿仍可创建；填写来源时，单据类型、单据 ID 和真实行 ID 必须同时提供。

来源必须属于当前组织、行必须属于所选单据，单据必须为 `APPROVED`。供应商或客户及物料必须与订单匹配，销售报价币种必须与订单一致。引用共享申请或报价需要相应模块查看能力和 `ALL` 范围；沿用入口对当前成员和创建能力的检查。

来源校验和订单、行、来源关联、幂等记录写入处于同一事务。读取来源使用 MySQL `FOR SHARE`，避免校验后并发修改来源。来源类型统一为大写，`linked_quantity` 保存当前订单行数量。本人重复提交沿用原重放规则，关联不会重复写入。

采购申请、销售报价响应新增可选 `lineId` 字段；无行的历史记录返回 null，不参与来源选择。页面使用真实 `lineId`，来源信息保存在对应订单行上。新加行独立，清空选择去掉来源，删除来源行不会把关联转移到剩余行，重新打开表单重置来源选择。

本阶段没有增加迁移，也不改写历史订单或来源关联。跨订单累计分配、重复来源行数量上限、报价时效及请求正文指纹仍需独立业务规则和验收。

验证：完整后端测试 205 项，失败、错误、跳过均为 0；其中 TradeInventoryMySqlTest 24 项实际执行。前端 32 项测试包含 8 项来源表单操作回归。静态检查、类型检查与生产构建见当次交付记录。

本次没有运行旧 HTTP 探测脚本，没有新增外部安全测试。组件测试使用原生下拉框替身，不等同于真实浏览器 Element Plus 操作验收。远程 CI 与全量端到端测试未计为通过。
