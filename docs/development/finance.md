# 财务核算开发规则

## 1.0 目标

阶段 06 提供单组织演示版的总账、会计期间、应收应付、收付款、试算平衡、利润表、资产负债表和账龄分析。所有账务数据保留 `organization_id`，业务单据通过来源类型和来源 ID 与凭证建立幂等关联。

## 记账规则

每张已过账凭证必须满足：

- 至少包含两条分录；
- 每条分录只能有借方或贷方金额，不能同时有值；
- 借方合计必须等于贷方合计，且大于零；
- 所用科目必须启用且允许过账；
- 记账日期所属会计期间必须存在且为开放状态。

核心业务自动记账映射如下：

| 业务事件 | 借方 | 贷方 |
| --- | --- | --- |
| 采购入库 | 1400 库存资产 | 2000 应付账款 |
| 销售订单应收依据 | 1100 应收账款 | 4000 销售收入 |
| 销售出库 | 5000 销售成本 | 1400 库存资产 |
| 客户收款 | 1000 现金 | 1100 应收账款 |
| 供应商付款 | 2000 应付账款 | 1000 现金 |
| 库存增加调整 | 1400 库存资产 | 5000 库存差异 |
| 库存减少调整 | 5000 库存差异 | 1400 库存资产 |

同一组织、来源类型和来源 ID 只能生成一张凭证。已过账凭证不允许直接修改；1.0 仅保留作废实体状态，反转凭证和完整更正流程放入 2.0。

## 应收应付

1.0 使用销售订单创建应收依据，采购入库创建应付单据。收付款必须引用对应单据，金额不得超过未结余额，付款后更新 `OPEN`、`PARTIALLY_SETTLED` 或 `SETTLED` 状态，并同步生成总账凭证。

账龄以查询日与到期日计算，区间为 `CURRENT`、`1_30`、`31_60`、`61_90` 和 `90_PLUS`。1.0 的付款方式为银行、现金和其他，不包含银行对账。

## 1.0 边界

本阶段不实现税务合规发票、银行对账、完整多币种重估、自动汇兑损益、预算控制、现金流量表和复杂结转。多组织正式结算、细粒度财务权限、附件和外部财务系统集成按 2.0 规划。

## 验收标准

- 手工凭证不平衡时 API 返回校验错误；
- 采购入库、销售订单、销售出库、客户收款和供应商付款均生成借贷平衡凭证；
- 已关闭期间拒绝新增过账；
- 试算平衡的借方合计等于贷方合计；
- 财务工作台能够展示真实 API 数据，并支持中英文切换；
- 财务服务单元测试覆盖平衡校验和会计期间建立。
