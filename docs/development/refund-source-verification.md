# 退款来源和余额约束（R6-E）

本批先补后端退款基础规则，页面入口将在后续批次开放。普通收款/付款的原有请求无需新增字段；退款请求必须传 `originalPaymentId`，返回详情包含该来源 ID。客户退款引用已过账收款，供应商退款引用已过账付款，来源必须属于当前组织、同交易方、同币种和本位币。退款沿用原单会计汇率与汇率日期，记账日期不得早于原单。本批不支持另填汇率退款及其差额结转。

每张原收付款可退金额 = 原金额 − 已核销金额 − 引用该单的 DRAFT/POSTED 退款金额。退款金额最多4位小数，不依赖数据库舍入推断占用与凭证金额。退款草稿即占用余额，过账会重新校验；过账时排除自身占用，避免重复扣减。分次退款允许，普通收付款核销也须保留退款占用。解除原核销释放余额，原核销与解除历史保留。退款不能核销普通发票；普通收款只核销销售发票，普通付款只核销供应商发票，贷项不作为普通核销目标。

所有创建收付款、退款过账、核销和解除核销共用现有组织财务事务锁，防止并发退款/核销同时占用余额。相同退款请求幂等重放返回原单，不增加占用；同键不同来源、金额、交易方、账户、日期、币种、汇率或参考信息返回冲突。沿用现有权限、会计期间及凭证借贷平衡规则。

V21 只新增 nullable 来源列及查询索引，不猜测历史退款来源，不删除或重写历史记录。若同交易方同币种存在没有来源的历史 DRAFT/POSTED 退款，新增退款和普通核销暂停，必须先完成历史人工对账与后续来源恢复。不能通过忽略该记录来重新使用余额。没有新增自动历史补录工具。

已付款发票退回时，先显式解除必要的原核销，再依原发票创建和过账贷项，最后从释放后的原收付款余额创建退款；贷项本身不生成现金，也不凭空增加可退余额。对实际未分配预收/预付同样允许退款。不支持无来源现金退款、退款再退款、任意不同汇率退款、贷项后续抵扣、退款撤销/草稿取消或完整历史修复；这些仍待后续。

验收使用既有隔离 MySQL `audit_flowora`、真实事务与合成组织：客户/供应商两侧分别原金额100 EUR、汇率1.3；创建退款40草稿后普通核销60，再过账退款，解除核销后退款剩余60，最终现金净额0。所有凭证逐张借贷平衡，来源关联和核销解除历史保留。并发两笔60退款只接受一笔草稿，余额占用60；回归覆盖幂等重放、额度、原汇率、核销占用与无来源历史暂停。这些为隔离业务数据库测试，不是浏览器或手工 HTTP 验收。

全部现有 GitHub CI 保留：Web、API、Windows Maven Wrapper、隔离 MySQL HTTP 回归及生产 Compose。没有额外手工安全探测、异常 HTTP 脚本、工作流或镜像改动。
