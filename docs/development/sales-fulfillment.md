# 阶段 05：销售与履约

## 目标

交付“销售报价 → 销售订单 → 出库 → 应收依据 → 收款”的可演示闭环，支持库存商品分批履约、服务商品跳过库存和客户分次付款。

## 业务规则

- 所有销售、出库、应收和收款记录携带 `organization_id`，接口只允许访问当前组织的数据。
- 报价保存客户、商品/服务、数量、单价、折扣、税率、币种和有效期；报价通过阶段 03 工作流审批后才可转为订单。
- 1.0 使用单行销售单据作为演示切片，底层表结构保留订单头/行关系，后续可扩展多行编辑。
- 销售订单创建后进入已确认状态，并保存来源报价引用；同时生成客户应收依据和到期日。
- 库存商品出库时必须引用订单行和订单仓库，出库数量不得超过剩余可履约数量，也不得造成负库存。
- 服务商品可以跳过库存扣减，但仍更新订单履约数量并保留出库/履约记录。
- 销售订单支持多次出库：部分出库为 `PARTIALLY_FULFILLED`，全部出库为 `FULFILLED`。
- 客户收款支持分次入账，累计收款不得超过应收未结余额；全部收款后应收状态为 `SETTLED`。
- 库存商品出库调用库存服务写入 `SHIPMENT` 流水，使用出库时的移动平均成本作为销售成本依据。

## 交付范围

- 后端：销售报价、报价审批、销售订单、销售出库、部分履约、应收依据、分次收款接口。
- 前端：销售报价/订单/应收三个工作台、报价转订单、出库和收款表单。
- 数据库：Flyway `V6__sales_fulfillment.sql`，包含销售单据、出库、应收和收款表。
- 接口契约：`docs/api/openapi.yaml` 中新增销售请求模型和接口路径。

## 阶段验收标准

1. 可创建销售报价；低于组织阈值的报价自动批准，高风险报价进入工作流待审批。
2. 已批准报价可创建销售订单，并保存来源报价、订单行、总金额和应收依据。
3. 销售订单可分批出库，剩余数量、订单状态和库存 `SHIPMENT` 流水正确。
4. 服务商品可跳过库存扣减，但仍能完成履约和应收跟踪。
5. 应收依据可多次收款；收款超过未结余额时请求被拒绝，结清后状态正确。
6. 组织隔离和角色边界生效：业务角色创建单据，仓库角色出库，财务角色收款，管理角色审批报价。
7. 前端和后端质量门禁通过：`pnpm verify:web` 与 Maven API 测试全部通过。

## 1.0 简化与 2.0 边界

本阶段的应收依据是销售订单产生的结算依据，不等同于完整税务发票；阶段 06 才负责总账凭证、税额过账和正式财务报表。

1.0 不实现退货、退款、红字单据、信用额度、客户门户、电子发票和多税率税区。这些能力进入 2.0 规划。
