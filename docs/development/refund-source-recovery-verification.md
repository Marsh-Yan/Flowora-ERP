# 历史退款来源恢复验收（R6-I）

退款管理新增明确来源恢复入口，要求当前组织ALL范围，并同时具有 finance:create 和 finance:post；页面查看仍需 finance:view。仅针对缺少 original_payment_id 的POSTED客户/供应商退款。无来源草稿沿用取消后重建流程，不自动推断或批量补填来源。

操作人逐笔选择退款和已核对原收付款，填写原因/依据并确认，提交双方当前版本。服务器在组织财务锁下检查原单为实际POSTED普通RECEIPT/PAYMENT、类型/交易方/币种/本位币一致、同汇率、日期合理、交易币额度及账面余额足够；原单已核销量与活动核销记录一致，退款没有活动核销、差额凭证或不一致账面依据。不同汇率或不一致旧账继续暂停，不回写差额或修改旧账。

恢复要求两笔业务均存在唯一、当前POSTED且未反转的实际凭证，凭证头与业务日期/币种/汇率/金额一致，两条分录分别完整借贷并按原率折算、归属同往来方，来源与退款使用同一实际往来控制科目。按锁定读取确认凭证当前状态，避免既有一致性快照忽略另一事务刚完成的来源凭证反转。恢复只增加来源与账面关联、双方版本和V24不可重复恢复记录，保存原因、操作人、双方原版本、双方实际凭证ID及请求键；不新增或改写凭证、不重新过账，因此允许已关闭期间的纯元数据核对。相同键与相同内容重试返回原结果，不同内容拒绝；已恢复不能重新指向别的原单。

恢复后退款按实际来源占用余额。若同交易方同币种还有其他无来源DRAFT/POSTED退款，新退款与普通核销仍保持暂停；须逐笔恢复或取消必要草稿后解除，不因为恢复一条就放行全部历史。页面不预选原单；目标、原因、版本、可用额度或相关元数据变化后重新确认。等待禁止重复/关闭，无自动重试；结果不确定且仍未恢复时，同内容明确重试保留key。关闭、组织/权限切换后的迟到回调丢弃。所有有查看权限的用户可查看持久化来源恢复原因、操作人与两张实际凭证ID。
