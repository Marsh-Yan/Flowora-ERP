# Flowora ERP 1.0 → 2.0 升级手册

> 版本范围说明（2026-10-02）：下文切换步骤和旧演练描述的是 V14→V15，不能直接用作当前 V19 上线批准。V16 后仍需运行 V17 库存切换、V18 数量核对及 V19 财务设置补缺；执行前阅读 [库存预检及切换规则](../development/inventory-cutover.md)和[组织财务与时间配置](../development/organization-finance-time.md)，保留数据库与附件备份。最新验收缺口见 [覆盖及待办](../development/audit-verification.md)。已执行的迁移不得修改或向下回滚；恢复必须在另一个明确的隔离目标演练。

## 升级原则

升级窗口内停止写入，先备份、后迁移、再核对。V15 将旧应收/应付转换为只读 `MIGRATED_LEGACY` 财务影子单据，不生成新凭证；每个组织创建 `LEGACY-STOCK` 复核仓。v1 读取继续可用，v1 业务写入改为 HTTP 426。

## 预检

使用外部凭据文件执行 `tools/upgrade/flowora-upgrade.ps1 -Stage Prepare`。必须满足：当前版本为 V14、孤立应收/应付均为 0、备份空间足够、MySQL 与 Redis 健康。记录旧应收、旧应付和凭证总数。

## 切换步骤

1. 宣布维护窗口，停止 Web/API 和外部写入，确认 outbox 不再增长。
2. 执行完整数据库和附件备份并校验 SHA-256。
3. 使用外部 Flyway 配置执行 `-Stage Migrate -ConfirmMigration`。
4. 核对 V15、影子应收=旧应收、影子应付=旧应付、迁移凭证=0、凭证总数不变、缺失复核仓=0。
5. 部署 2.0，执行登录、权限、财务读取、库存、工作流、分析和导出冒烟测试。
6. 观察 30 分钟后恢复入口流量，保留备份和升级报告。

## 回滚

V15 不执行向下迁移。若迁移或验收失败，保持服务停止：重建明确的目标库，从升级前备份恢复数据库与附件，部署原 1.0 产物，执行 V14 校验后恢复流量。已接受 2.0 新写入后不得直接回滚到 V14，需进入事件级恢复方案。
