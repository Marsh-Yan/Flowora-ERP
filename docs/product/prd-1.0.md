## 2. 产品概述

### 2.1 产品定位

Flowora-ERP 1.0 是一个面向贸易/批发型中小企业的 ERP 演示产品。产品以“业务单据、审批任务、库存/财务结果、活动时间线”四类信息为主线，让用户能够从一个工作台追踪业务从发起到完成的全过程。

1.0 不是面向特定国家上线的合规财务系统，也不包含制造、复杂仓储或外部系统集成。它的目标是提供一个可运行、可验证、可扩展的 ERP 核心闭环，并体现 Flowora 的流程优先和国际化产品特征。

### 2.2 当前仓库基线

当前仓库已经具备：

- Vue 3 + TypeScript + Vite + Element Plus 的后台壳和双语切换。
- Spring Boot API、统一响应结构、错误码结构和健康检查接口。
- MySQL/Flyway/Redis/Spring Session 的依赖准备。
- 工作台、销售、采购、库存、财务、流程、分析和系统管理导航入口。

当前尚未具备：

- 登录、用户、角色、组织数据和业务权限。
- 业务领域表、业务状态机和实际 API。
- 销售、采购、库存、财务和项目业务逻辑。
- 真实仪表盘数据、演示种子数据和完整业务测试。

### 2.3 需求调研依据

需求依据分为三类：

1. 仓库现状和已有项目章程：确定 Flowora 的工作台、国际化、流程和核心业务边界。
2. 公开领域资料：成熟 ERP 通常使用源单关联、部分履约、库存流水、自动记账和项目工时/费用关联。
3. 产品假设：当前没有真实企业访谈数据，因此本 PRD 中的用户痛点属于需要后续验证的产品假设，不宣称为统计结论。

参考资料：

- [ERPNext Selling](https://docs.frappe.io/erpnext/selling)：销售订单、交付、开票、付款和部分履约链路。
- [ERPNext Project](https://docs.frappe.io/erpnext/project)：项目与销售订单、工时、成本和客户的关联。
- [Odoo Sales](https://www.odoo.com/documentation/18.0/applications/sales/sales.html)：报价、销售订单、交付、开票和项目里程碑。
- [Odoo Timesheets](https://www.odoo.com/documentation/19.0/applications/services/timesheets.html)：项目工时、任务、权限和可计费工时。
- [Odoo Accounting](https://www.odoo.com/documentation/19.0/applications/finance/accounting.html)：复式记账和业务交易自动生成会计分录。
- [Odoo Inventory Valuation](https://www.odoo.com/documentation/19.0/applications/finance/accounting/get_started/inventory_valuation.html)：库存估值和移动平均成本方法。

## 3. 用户与业务目标

### 3.1 目标用户

| 角色 | 主要任务 | 1.0 权限定位 |
| --- | --- | --- |
| 管理员 | 组织、用户、角色、系统设置和演示数据 | 全部权限 |
| 业务专员 | 客户、供应商、报价、订单、采购申请和跟进 | 负责业务单据，不能修改已过账财务结果 |
| 仓库人员 | 入库、出库、调拨、盘点和库存调整 | 负责仓库操作，不能查看全部财务数据 |
| 财务人员 | 科目、凭证、发票、应收应付、收付款和报表 | 负责财务过账和财务报表 |
| 项目经理 | 项目、里程碑、任务、工时、费用和项目预算 | 负责项目数据和项目协同 |
| 管理层 | 审批、经营看板、财务和库存分析 | 只读经营数据，拥有审批权限 |

1.0 使用粗粒度角色。销售/采购、出纳/会计、审批人、项目成员等细分角色放入 2.0。

### 3.2 产品目标

- 让用户在一个工作台看到待办、业务健康度、库存和财务概况。
- 让采购和销售单据形成可追溯的源单链路。
- 让入库、出库、库存调整与总账结果保持一致。
- 让项目型服务能够关联销售订单、任务、工时、费用和可计费依据。
- 让中文和英文界面、组织时区、本位币和交易币种具备一致的数据口径。
- 提供稳定的演示账号和完整种子数据，使核心流程可以重复演示。

### 3.3 非目标

- 不实现生产制造、MRP、BOM、产能计划和高级采购计划。
- 不实现国家级税务申报、电子发票、EDI 或银行自动对账。
- 不实现批次、序列号、库位、先进先出和复杂仓储规则。
- 不实现可视化流程设计器和任意条件分支。
- 不实现 SSO、邮件通知、附件、客户门户和外部系统连接。
- 不承诺生产环境合规性、SLA 或多租户运营能力。

## 5. 核心业务流程

### 5.1 采购到付款

```text
采购申请 → 审批 → 采购订单 → 审批 → 入库 → 应付账款 → 付款
```

规则：

- 采购申请必须包含申请人、供应商、仓库、商品/服务、数量、单价、币种和期望日期。
- 采购订单只能从已批准的采购申请生成，也允许业务专员直接新建后进入审批。
- 入库数量可以小于订单剩余数量；超额入库默认禁止。
- 入库后更新库存余额、库存流水、移动平均成本和相关会计结果。
- 付款可以分次完成；付款总额不得超过应付未结余额。

### 5.2 订单到收款

```text
销售报价 → 审批/确认 → 销售订单 → 出库 → 应收账款 → 收款
```

规则：

- 报价保存客户、报价有效期、商品/服务、数量、价格、折扣、税率和币种。
- 已确认报价可以转换为销售订单，转换时保留来源引用。
- 销售订单可以包含库存商品和非库存服务。
- 库存商品需要出库；服务项目可以跳过出库直接形成可开票依据。
- 出库支持分批完成；出库数量不得超过订单剩余可履约数量。
- 收款可以分次完成；完成后更新应收余额和单据状态。

### 5.3 项目交付

```text
销售订单/客户 → 项目 → 里程碑 → 任务 → 工时/费用 → 进度与预算 → 可计费依据
```

规则：

- 项目可以关联客户和销售订单，也可以独立创建。
- 项目包含目标日期、负责人、预算收入、预算成本和状态。
- 任务包含负责人、优先级、截止日期、状态和所属里程碑。
- 工时和费用必须关联项目；可标记为可计费或不可计费。
- 可计费工时/费用形成待开票依据，不直接绕过审批生成已收款记录。

## 6. 状态机

### 6.1 通用单据状态

```text
DRAFT → SUBMITTED → APPROVED → CONFIRMED → COMPLETED
                  ↘ REJECTED
                          ↘ CANCELLED
```

约束：

- `DRAFT` 可以编辑和删除。
- `SUBMITTED` 只能补充评论或撤回，不能修改核心金额和数量。
- `REJECTED` 可以复制为新单据，不能直接改成已批准。
- `APPROVED` 可以进入后续执行单据。
- `CONFIRMED` 后只能通过履约、结算或冲销动作改变结果。
- `COMPLETED` 和 `CANCELLED` 只读。

### 6.2 销售与采购执行状态

| 状态 | 含义 |
| --- | --- |
| Draft | 草稿 |
| Pending Approval | 等待审批 |
| Approved | 已审批，可执行 |
| Partially Fulfilled | 已部分履约 |
| Fulfilled | 已完成全部履约 |
| Partially Settled | 已部分结算 |
| Settled | 已全部结算 |
| Cancelled | 已取消 |

### 6.3 库存流水状态

```text
DRAFT → POSTED
      ↘ VOIDED
```

`POSTED` 流水不可编辑。错误流水必须通过反向流水或经审批的库存调整纠正。

### 6.4 项目和任务状态

项目：`PLANNED → ACTIVE → AT_RISK → COMPLETED → ARCHIVED`。

任务：`TODO → IN_PROGRESS → BLOCKED → DONE`，允许从 `BLOCKED` 回到 `IN_PROGRESS`。

### 6.5 审批任务状态

```text
OPEN → APPROVED
    ↘ REJECTED
    ↘ TRANSFERRED → OPEN
    ↘ CANCELLED
```

## 7. 审批与协同规则

### 7.1 固定审批范围

- 采购申请、采购订单。
- 销售报价、销售订单。
- 超过风险阈值的库存调整。

普通入库、出库、仓间调拨、收付款和项目任务不重复进入管理层审批。

### 7.2 金额阈值

- 审批阈值是组织设置，不等同于可视化流程配置。
- 演示环境默认阈值为本位币等值 10,000。
- 低于阈值的核心单据由业务专员提交后自动通过基础审批；达到或超过阈值的单据创建管理层审批任务。
- 库存调整按调整金额或调整数量风险判断；达到阈值时必须由管理层审批。

### 7.3 协同记录

- 所有单据、项目和任务都展示活动时间线。
- 用户可以添加评论，但 1.0 不支持附件和 `@` 成员。
- 系统自动记录创建、提交、审批、驳回、转交、过账、取消和冲销。
- 通知只使用站内通知和任务箱，不发送邮件或短信。

## 8. 财务与库存规则

### 8.1 复式记账

- 每张已过账凭证必须满足借方总额等于贷方总额。
- 财务人员和管理员可以录入手工调整凭证。
- 已过账凭证不可编辑或删除，只能通过冲销凭证纠正。
- 会计期间关闭后禁止新增或修改该期间的过账结果。

### 8.2 主要自动凭证

| 业务动作 | 借方 | 贷方 |
| --- | --- | --- |
| 销售出库 | 销售成本 | 库存商品 |
| 销售开票 | 应收账款 | 主营收入、应交税费 |
| 客户收款 | 银行/现金 | 应收账款 |
| 采购入库 | 库存商品 | 应付暂估/应付账款 |
| 供应商发票 | 应付暂估/费用、进项税 | 应付账款 |
| 供应商付款 | 应付账款 | 银行/现金 |
| 库存盘盈 | 库存商品 | 库存盘盈 |
| 库存盘亏 | 库存盘亏 | 库存商品 |

具体科目由组织科目映射配置决定；演示环境提供默认科目表。

### 8.3 库存计价

- 1.0 使用移动加权平均成本。
- 入库后按以下公式更新平均成本：

```text
新平均成本 = (原库存数量 × 原平均成本 + 入库数量 × 入库单价) / 新库存数量
```

- 出库按出库时的当前平均成本结转销售成本。
- 库存余额按组织、仓库、商品维度维护。
- 默认禁止负库存；管理员不能通过普通出库绕过库存校验。

### 8.4 税率与币种

- 组织设置本位币和时区。
- 业务单据可选择交易币种，并保存交易发生时使用的汇率。
- 1.0 只支持单一税率或免税，税率由组织设置维护。
- 不实现地区税区、复杂税率叠加、税务申报和电子发票合规。

## 9. 领域模型

所有业务表必须包含 `organization_id`、`created_at`、`created_by`、`updated_at`、`updated_by` 和版本字段；过账流水额外包含不可变引用和过账时间。

### 9.1 身份与组织

- `organization`：组织名称、本位币、时区、审批阈值、默认税率。
- `user`：登录名、密码哈希、显示名、状态、组织归属。
- `role` / `permission`：1.0 粗粒度角色和权限集合。
- `session`：Redis 会话和过期时间。
- `audit_event`：操作者、动作、资源类型、资源 ID、旧值摘要、新值摘要、时间和请求 ID。

### 9.2 主数据

- `customer`：客户编码、名称、联系人、地址、币种、付款条件、状态。
- `supplier`：供应商编码、名称、联系人、地址、币种、付款条件、状态。
- `item`：商品/服务编码、名称、类型、单位、销售价、采购价、平均成本、税率、是否维护库存。
- `warehouse`：仓库编码、名称、地址、状态。
- `currency` / `exchange_rate`：币种和生效日期汇率。
- `tax_rate`：税率、是否免税、生效日期。
- `account`：科目编码、名称、类型、父科目、可过账标记。

### 9.3 业务单据

- `purchase_request` / `purchase_request_line`。
- `purchase_order` / `purchase_order_line`。
- `purchase_receipt` / `purchase_receipt_line`。
- `sales_quote` / `sales_quote_line`。
- `sales_order` / `sales_order_line`。
- `delivery` / `delivery_line`。
- `receivable_document` / `payable_document`。
- `payment`：收款或付款方向、金额、币种、账户、关联单据。

每张后续单据必须保存来源单据类型、来源单据 ID 和来源行 ID，禁止通过复制文字代替业务关联。

### 9.4 库存、财务和项目

- `stock_balance`：组织、仓库、商品、数量、平均成本、库存价值。
- `stock_ledger_entry`：来源单据、方向、数量、单价、金额、余额、过账时间。
- `stock_transfer`、`stock_count`、`stock_adjustment`。
- `journal_entry` / `journal_line`：凭证头、借贷分录和业务来源。
- `accounting_period`：期间、开始日期、结束日期、状态。
- `project`、`milestone`、`project_task`、`timesheet`、`project_expense`、`project_budget`。
- `workflow_task`、`notification`、`comment`、`activity_event`。

## 11. API 与工程契约

### 11.1 通用约定

- API 前缀为 `/api/v1`。
- 成功响应沿用 `ApiResponse<T>`：`data` 和 `requestId`。
- 失败响应沿用 `ApiError`：`code`、`messageKey`、`args`、`requestId`。
- API 只返回 message key，不返回固定中文文本。
- 时间使用 ISO 8601；金额使用定点数；服务端 Java 使用 `BigDecimal`。
- 所有写操作需要鉴权、组织边界校验、审计事件和幂等保护。

### 11.2 资源分组

```text
/api/v1/auth
/api/v1/organizations
/api/v1/masters/customers
/api/v1/masters/suppliers
/api/v1/masters/items
/api/v1/masters/warehouses
/api/v1/masters/currencies
/api/v1/masters/taxes
/api/v1/masters/accounts
/api/v1/procurement
/api/v1/sales
/api/v1/inventory
/api/v1/finance
/api/v1/workflow
/api/v1/projects
/api/v1/reports
/api/v1/demo/reset
```

OpenAPI 负责完整请求/响应字段；PRD 负责业务语义、状态和验收，两者不得出现相互矛盾的状态定义。

### 11.3 会话安全

- 使用本地账号和 Redis 会话。
- 密码只保存 BCrypt 哈希。
- 会话 cookie 使用 HttpOnly、Secure、SameSite 属性。
- 所有状态变更请求需要 CSRF 防护或等价的同源防护。
- 登录失败、权限拒绝、资源不存在和业务状态冲突使用稳定错误码。

## 12. 工作台与报表

工作台至少展示：

- 待审批单据数量。
- 待处理任务和即将逾期任务。
- 销售订单金额、采购订单金额和本月收付款。
- 库存总值、低库存商品和库存周转概览。
- 应收、应付和逾期账款。
- 项目预算、实际成本、进度和风险项目。
- 最近活动时间线。

报表至少包括：

- 总账。
- 试算平衡表。
- 应收账龄。
- 应付账龄。
- 利润表。
- 资产负债表。
- 库存余额和库存流水。
- 销售履约和采购履约。
- 项目预算/实际和工时汇总。

所有报表必须支持组织范围、日期范围和 CSV 导出；涉及金额的报表必须明确本位币和交易币种口径。

## 13. 非功能需求

- 桌面后台优先，保证 1280px 以上完整体验；平板和窄屏提供基础查看及待办操作。
- 前端继续使用 Vue 3、TypeScript、Vite、Element Plus、Pinia 和 vue-i18n。
- 后端继续使用 Java 25、Spring Boot、Spring Security、JPA、Flyway、MySQL 和 Redis。
- Dashboard 和常用列表在演示数据规模下目标响应时间不超过 2 秒。
- 业务写操作必须在一个事务内完成单据、库存流水、会计凭证和审计事件写入。
- 自动记账必须幂等：同一业务单据重复提交不能生成重复凭证或重复库存流水。
- 所有异常响应携带 `requestId`，日志不得记录真实密码、token 或个人敏感数据。
- 不能将真实个人信息、企业信息、账号密码或生产连接串提交到仓库。

## 15. 分阶段实施与验收

### 阶段 00：PRD 与技术契约

交付本文件、领域术语、状态机、权限矩阵、API 资源分组、验收标准和 2.0 边界。

验收：研发可以依据本文件拆分前后端任务，不需要重新决定核心业务规则。

### 阶段 01：平台基础

交付登录、退出、会话、用户、角色、组织、API 错误、路由守卫、请求追踪和基础审计。

验收：未登录用户不能访问业务页；角色和组织边界测试通过。

### 阶段 02：主数据与系统设置

交付客户、供应商、商品、仓库、币种、汇率、税率、科目、组织设置和 CSV 能力。

验收：主数据支持校验、搜索、分页、引用检查和导入失败反馈。

### 阶段 03：流程与协同中心

交付任务箱、通知、审批、评论、活动时间线和固定审批规则。

验收：提交、审批、驳回、转交、完成和审计链路可重复验证。

### 阶段 04：采购与库存

交付采购申请、采购订单、入库、多仓库、库存流水、调拨、盘点、调整和移动加权平均。

验收：采购入库正确影响库存余额和库存流水，库存高风险调整需要审批。

### 阶段 05：销售与履约

交付销售报价、销售订单、出库、部分履约、应收依据和收款。

验收：销售订单可以分批出库，剩余数量、状态和金额正确。

### 阶段 06：财务核算

交付总账、凭证、应收应付、收付款、会计期间和财务报表。

验收：采购、销售、库存和收付款动作生成正确的借贷平衡凭证。

### 阶段 07：项目协同

交付项目、里程碑、任务、工时、费用、预算、进度和可计费依据。

验收：项目能够关联销售订单，并展示预算、实际成本、工时和可计费金额。

### 阶段 08：工作台与国际化

交付真实经营看板、全局搜索、打印、导出、中英双语、时区、多币种和响应式适配。

验收：看板数据来自真实业务；语言、金额、日期和时区显示一致。

### 阶段 09：演示数据与质量加固

交付种子数据、重置能力、并发/幂等、安全、错误处理、回归测试和文档补全。

验收：可从空库完整演示三条主流程，重复操作不会产生重复库存或凭证。

### 阶段 10：1.0 发布验收

交付全量回归、发布说明、已知限制、2.0 路线图和最终验证结果。

验收：

```powershell
pnpm verify:web
mvn -B -pl services/api -am test
```

## 16. 测试要求

### 单元测试

- 状态机合法/非法迁移。
- 角色权限和组织隔离。
- 税额、汇率和金额舍入。
- 移动加权平均成本。
- 借贷平衡和凭证生成。
- 审批阈值和任务路由。

### API 测试

- 登录、退出和会话过期。
- 未授权、无权限、跨组织访问。
- 主数据 CRUD、分页、搜索和导入失败。
- 单据创建、提交、审批、驳回、取消和幂等。
- 库存、凭证、应收应付和项目结果联动。

### 端到端测试

1. 采购申请 → 采购订单 → 入库 → 应付 → 付款。
2. 销售报价 → 销售订单 → 出库 → 应收 → 收款。
3. 销售订单 → 项目 → 任务/工时/费用 → 可计费依据。
