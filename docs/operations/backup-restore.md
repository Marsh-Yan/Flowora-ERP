# 备份、恢复与灾难恢复

目标 RPO 为 24 小时，RTO 为 4 小时。数据库与附件必须在同一备份窗口生成，并保存在主机之外、启用加密和保留策略的介质中。

## 备份

`tools/operations/backup.ps1` 使用外部 MySQL defaults 文件读取凭据，生成一致性 SQL 备份、附件压缩包和 SHA-256。执行后将两份文件及哈希清单上传到受控备份库。Redis 仅保存会话和可重建状态，不作为业务事实来源。

## 恢复

1. 隔离目标环境并停止入口流量和后台任务。
2. 校验备份哈希，创建明确命名的空数据库。
3. 使用 `tools/operations/restore.ps1 -ConfirmRestore` 恢复数据库；附件解压到空目录，禁止覆盖不明目标。
4. 运行 Flyway `validate`、升级控制总数和关键闭环查询。
5. 启动 API，检查 readiness、登录、权限、附件下载和业务读操作，再恢复流量。

恢复脚本具有破坏性确认开关，禁止将生产库名作为演练目标。每季度至少在隔离环境完成一次恢复演练并记录实际 RPO/RTO。
