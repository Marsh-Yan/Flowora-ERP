# Flowora ERP 2.0.0 M4

Status: review candidate

## Outcome

M4 completes the finance and project-accounting backbone defined by the 2.0 PRD. Operational source events from M3 can now become formal customer or supplier documents, balanced journals, settlements, bank reconciliation records and project billing evidence.

## Delivered

- formal sales invoices, supplier invoices, customer credit notes and supplier credit notes;
- business, accounting and exchange-rate dates with transaction/base currency snapshots;
- supplier receipt/order/invoice matching, tolerance checks and exception approval;
- configurable posting mappings and balanced automatic journals with project, party and source-line dimensions;
- receipt/payment creation, posting, allocation, allocation reversal and realized exchange differences;
- journal reversal, accounting-period close checks and controlled reopen events;
- bank statement import, duplicate detection, reconciliation and reconciliation reversal;
- budget versions, budget execution reporting and currency revaluation;
- finance cockpit, trial balance and management dashboard;
- project membership, approval-based billing basis, billing configuration, draft invoice generation and profitability;
- V14 migration, M4 permissions, deterministic demo reset and a demo USD bank account;
- Web finance cockpit and project billing/profitability panels in Chinese and English.

## Compatibility

- `/api/v1` remains available and unchanged.
- V1–V13 migrations remain hash-frozen; M4 adds only V14.
- M3 source documents and stock movements remain the operational evidence for finance matching.
- The release-stage marker advances to `M4`; the global business-write feature flag remains independent.

## Verification completed

- empty-schema V1–V14 migration passed on MySQL 8;
- deterministic demo startup and reset passed after adding explicit role-permission cleanup;
- real API smoke tests passed for invoice idempotency, posting and balanced journal creation;
- receipt posting, allocation and invoice settlement passed end to end;
- project approval, billing-basis, draft-invoice and profitability linkage passed;
- backend suite passed: 75 tests, zero failures and zero errors;
- Web lint, TypeScript check, unit test and production build passed;
- local health, release stage, Flyway version and M4 seed counts were verified against an isolated database.

## Review acceptance

Manual review should cover one sales invoice, one supplier three-way match including an exception, customer receipt allocation, allocation reversal, bank reconciliation/reversal, period close/reopen and a project billing run. All posted journals must remain balanced in both transaction and base currency.

## Review focus

- invoice and credit-note cumulative source quantities;
- posting mapping completeness and closed-period enforcement;
- payment and allocation concurrency boundaries;
- bank import duplicate keys and reconciliation reversibility;
- project billing-basis consumption under repeated or concurrent requests;
- period-close evidence and permission separation for posting, exception approval and reopen.
