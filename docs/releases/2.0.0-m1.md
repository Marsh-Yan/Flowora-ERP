# Flowora ERP 2.0 M1 验收说明

## 阶段定位

M1 建立 2.0 后续业务域共同复用的生产化平台。本阶段不实现 M2 工作流编排或 M3/M4 业务闭环，只交付身份、组织、权限、审计和主数据底座。

## 交付内容

### 身份与会话

- `local`/`demo` 数据库配置使用 `flowora_user_account` 作为正式认证来源；`standalone` 才保留内存演示账号。
- 用户名按实例唯一、不区分大小写；用户状态支持邀请、活动、锁定和禁用。
- 默认连续 5 次失败锁定 15 分钟，阈值和时长具有安全边界。
- 密码长度 12–128，禁止用户名和常见弱密码，保留最近 5 个密码摘要。
- 改密后当前会话退出；Redis 会话可列出和逐个撤销。
- TOTP 密钥使用 AES-GCM 加密保存，提供 10 个一次性 BCrypt 恢复码。
- 登录、失败登录、组织切换、改密、MFA 与会话撤销写入安全审计。

### 组织与权限

- 组织支持父子关系、活动/归档状态和业务口径设置。
- 部门支持树结构、负责人、停用和乐观锁版本。
- 用户通过成员关系进入组织；组织切换会重新加载角色和权限并轮换会话 ID。
- 权限采用 `资源:动作` 代码，角色按组织定义权限集合和 `ALL/DEPARTMENT/SELF/ASSIGNED` 数据范围。
- v2 管理接口全部执行服务端权限判断，不接受客户端传入组织作为授权依据。
- 用户、成员、角色和组织敏感操作要求原因并写入变更审计。
- 禁止禁用最后一个有效实例管理员。

### 主数据平台

- V11 增加商品 `NONE/LOT/SERIAL` 追踪方式、层级库位、复合税规则、银行账户和编号规则。
- 库位类型包含普通、收货、发货、冻结、退货和报废。
- 有库存流水的商品禁止改变追踪方式。
- v2 库位与商品追踪更新使用 `If-Match` 乐观锁，冲突返回 `OPTIMISTIC_LOCK_CONFLICT`。
- 组织归档后成员关系同时停用；所有新主数据能力强制使用认证组织。

### Web 应用壳

- 前端认证迁移到 `/api/v2/session`。
- 登录页支持 `MFA_REQUIRED` 二阶段挑战和恢复码。
- 侧栏按有效权限动态显示；路由守卫提供第二层用户反馈，服务端仍是授权权威。
- 应用壳支持有效组织切换。
- 新增“平台与权限”和“账户安全”页面，覆盖成员、角色、部门、权限、密码、MFA 和活动会话。

## 数据迁移

- `V10__identity_organization_acl.sql`：身份、组织成员、部门、权限、数据范围、密码历史、MFA 与安全事件。
- `V11__master_data_platform.sql`：信用策略、商品追踪、库位、复合税、银行账户和编号规则。
- V1–V9 保持冻结；迁移测试继续验证其归一化摘要。
- 演示种子已切换为 BCrypt 数据库账号，并重建 M1 成员关系与角色关联。

## 运行配置

连接 MySQL/Redis 的 `local` 或 `demo` 配置必须提供：

```text
DB_USERNAME
DB_PASSWORD
REDIS_PASSWORD
FLOWORA_MFA_ENCRYPTION_KEY   # 至少 32 个字符，生产环境由密钥系统注入
```

生产环境同时必须设置 `FLOWORA_COOKIE_SECURE=true`，并使用精确的 CORS 来源列表。

## 自动验收

- API：原 1.0 回归测试、v2 会话、密码策略、TOTP、数据范围四象限及 V10/V11 契约测试。
- Web：ESLint、Vue TypeScript、Vitest 和 Vite 生产构建。
- 发布门：仓库根目录执行 `pnpm verify:release`。

## 审核重点

1. 数据库认证是否完全替代生产配置中的内存账号。
2. A/B 组织资源不能通过 ID 猜测、请求体组织字段或角色缓存交叉访问。
3. 角色变更后的新请求重新加载有效权限，敏感变更均具有原因和请求 ID。
4. V10/V11 可在空库和 1.0 样本库迁移；V1–V9 摘要不变。
5. MFA 密钥、密码和恢复码不会以明文写入数据库、日志或审计。

## 已知非阻断项

- 当前前端主包仍超过 500 kB，M1 新页面未显著改变既有包体问题；代码分包继续作为性能治理项。
- 真实 MySQL/Redis 迁移回放、并发登录和恢复演练属于提交 PR 前必须记录结果的环境验收项；若本机未配置依赖，CI 仅覆盖无需外部服务的自动测试。
