# Flowora ERP 2.0.0 M3

Status: review candidate

## Outcome

M3 establishes the sales, procurement and advanced-inventory transaction backbone required by the 2.0 PRD. It supports multi-line documents, partial fulfillment, dimension-level stock control, reverse flows and auditable finance source events while leaving formal accounting documents to M4.

## Delivered

- multi-line sales and purchase orders with currency, per-line price/discount/tax snapshots and deterministic four-decimal rounding;
- source-line links for one-to-many conversion, partial fulfillment and reverse-flow quantity reconciliation;
- optimistic document confirmation/cancellation and idempotent order creation;
- warehouse/location/item/lot/serial inventory dimensions with non-negative balance constraints;
- partial receiving with accepted/rejected quantities, weighted-average cost and lot/serial validation;
- sales-order reservations, partial consumption, manual release and expiry release;
- shipment and transfer posting with row locking, availability checks and serial state transitions;
- stock count snapshots, difference posting and scoped inventory freezes;
- sales returns and purchase returns with source validation, cumulative quantity guards and disposition handling;
- immutable stock movements linked to source document, source line, actor and idempotency request;
- pending-finance source events using the transaction currency and reconcilable quantity/amount payloads;
- v2 REST contracts and Web workbench support for multi-line order entry, dimension-level availability and movement trace;
- V13 migration, M3 permission grants, deterministic demo reset updates and migration contract tests.

## Compatibility

- `/api/v1` remains available and its existing contracts are unchanged.
- V1–V12 migrations remain hash-frozen.
- M3 adds only V13.
- Formal customer/supplier invoices, credit notes, payments, journals and reconciliation remain M4 responsibilities.
- The v2 release-stage marker advances to `M3`; the global business-write feature flag remains independently controlled.

## Data and concurrency guarantees

- balance rows are locked before reservation, shipment, transfer, return or count mutation;
- database checks prevent negative on-hand/reserved quantities and invalid reservation consumption;
- unique request keys prevent duplicate stock movements and duplicate order creation;
- shipment, receipt and return updates enforce remaining source quantities in the same transaction;
- lot and serial uniqueness plus serial state transitions prevent duplicate serial use;
- every movement preserves its source document, source line, actor, request key and value snapshot.

Manual review should cover multi-line create/confirm, partial receipt, concurrent reservation, partial shipment, transfer, count, both return directions, lot/serial trace and finance-source reconciliation before this release candidate is merged.

## Review focus

- quantity conservation across order, reservation, fulfillment and return columns;
- lock ordering and retry behavior under concurrent reservations and shipments;
- lot/serial lifecycle and quality dispositions;
- amount rounding, transaction currency propagation and M4 source-event semantics;
- permission boundaries for sensitive posting, freezing, returns and finance-source inspection;
- usability of multi-line entry and trace navigation in the three operational workbenches.
