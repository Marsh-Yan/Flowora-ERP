# Flowora ERP 2.0.0 M2

Status: review candidate

## Outcome

M2 delivers the common workflow and collaboration platform planned in the 2.0 PRD while retaining the v1 API compatibility surface.

## Delivered

- versioned workflow templates with declarative matching, publish/retire lifecycle and immutable runtime snapshots;
- serial, parallel-all and parallel-any approvals with explicit decision history;
- user, role, department manager, document owner and requester manager resolution;
- requester withdrawal, approver transfer/return/reject/approve and administrator termination;
- bounded delegation with cycle prevention and original/actual actor traceability;
- overdue task scan and transactional outbox with attempts, retry, dead-letter and idempotent replay;
- organization-scoped comments, explicit mentions, activity timeline and notification inbox;
- staged private attachment storage with size/type validation, SHA-256 and authorization on every download;
- Web inbox, decision trail, collaboration drawer and permission-gated template designer;
- V12 migration, M2 permissions, OpenAPI update and engineering guide.

## Compatibility

- `/api/v1` remains unchanged.
- V1 migrations V1-V9 remain hash-frozen.
- V10 is corrected to quote the MySQL 8 reserved column name `sensitive`; this intentionally changes the previously merged but non-runnable V10 checksum. Any environment reporting a successful V10 with a different checksum must be reviewed before migration and must not be repaired automatically.
- V11 remains unchanged.
- M2 adds only V12.
- v2 business write activation remains controlled separately from legacy compatibility.

## Verification gate

- Local MySQL 8 migrations pass both from an empty schema through V1-V12 and from the backed-up V9 sample through V10-V12; Flyway reports version 12 with no failed migration.
- Local API startup passes with `/actuator/health` returning `UP` and the version endpoint reporting stage `M2`.
- API full suite passes: 63 tests, zero failures or errors.
- Web TypeScript check and production build pass.
- V12 contract checks cover runtime snapshots, decision trace, collaboration, attachment and outbox storage.
- Manual acceptance must cover a purchase request and sales quote, a published-version change during a running instance, stale task version, delegation cycle, overdue notification, dead replay and revoked attachment access.

- Demo profile migration, deterministic seed/reset and health check pass on an isolated database.
## Review focus

- workflow transition semantics and requester/admin boundaries;
- approver resolution for real organization hierarchies;
- storage root, MIME allowlist and maximum file size;
- outbox retry/backoff and operational replay;
- visual usability of the single-step quick designer versus future advanced multi-step editing.
